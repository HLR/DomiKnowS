# EAI_Operation

This document describes the operational flow of the Embodied Agent Interface
(EAI) two-stage training pipeline. Stage 1 learns action plans from reference
sequences. Stage 2 starts from the best Stage 1 policy and refines it using
simulator outcomes, SimpleTL goal progress, and world-graph constraints.

## Operation at a glance

```text
EAI task row
   |
   +-- natural-language task and instruction
   +-- SimpleTL goal
   +-- initial/task-world information
   +-- reference action trajectory
   |
   v
Stage 1: supervised teacher forcing
   |
   +-- token-level cross-entropy through the first EOS
   +-- semantic validation after every epoch
   +-- restore and save the best semantic checkpoint
   |
   v
Stage 1 exploration gate
   |
   +-- fail: retain Stage 1 and skip reinforcement learning
   +-- pass: reuse the same Qwen, LoRA, adapter, graphs, vocabulary, and DFA
   |
   v
Stage 2: reinforcement learning plus supervised anchor
   |
   +-- sample graph-constrained trajectories
   +-- simulate actions and evaluate the actual SimpleTL goal
   +-- apply REINFORCE using within-task reward advantages
   +-- add teacher-forced gold-token cross-entropy
   |
   v
Two-stage checkpoint and semantic evaluation
```

## Shared task representation

Both stages consume the same prepared EAI example. For a book task, the Qwen
user message is conceptually:

```text
Task: Find and read a book
Instruction: Find the book, grab it, then read it.
SimpleTL goal: (exists x0. (GRAB(x0))) then exists x0. (READ(x0))
Available entity types: novel
```

The reference trajectory is converted to EAI vocabulary labels:

```text
find, novel_1000, grab, novel_1000, read, novel_1000, <eos>
```

The user message remains constant across token positions. The assistant-side
prefix changes as labels are supplied by teacher forcing or generated by the
policy. Qwen3 thinking is disabled, and the native chat template contributes
one assistant-generation marker.

The model predicts over the EAI action/entity vocabulary rather than Qwen's
entire native vocabulary. The default pretrained label adapter starts from
Qwen output-embedding vectors and adds a trainable low-rank residual, bias, and
temperature. In the Qwen+LoRA configuration, base Qwen weights remain frozen;
LoRA and label-adapter parameters are trainable in both stages.

## Stage 1: supervised exact-match pretraining

### Objective

Stage 1 teaches the policy to imitate the benchmark reference trajectory. The
name "exact-match pretraining" describes the desired sequence behavior, but
the differentiable objective is token-level cross-entropy:

```text
L_stage1 = mean_t[-log p(correct_label_t | prompt, gold_prefix_<t)]
```

This supplies a correct target at every meaningful sequence position.

### 1. Build the gold sequence

The reference action trajectory is normalized into alternating action and
argument labels, followed by EOS. Truncation preserves action/argument
atomicity: an object-taking action is never left at the end without its object.
Remaining positions are padded with EOS to `max_steps`.

Example:

```text
Targets:
  [find, novel_1000, grab, novel_1000, read, novel_1000, EOS]
```

### 2. Shift the targets for teacher forcing

The input sequence is shifted right. An EOS label in position zero acts as the
internal start sentinel:

```text
Input prefix labels:
  [START, find, novel_1000, grab, novel_1000, read, novel_1000]

Prediction targets:
  [find, novel_1000, grab, novel_1000, read, novel_1000, EOS]
```

At position `t`, the policy therefore sees the correct labels before `t`, even
if its unconstrained prediction at an earlier position would have been wrong.

### 3. Run Qwen and the EAI label adapter

For one example, Qwen receives one tokenized user prompt followed by the gold
assistant prefix. Boundary positions identify the hidden state that predicts
each next EAI label. A causal forward pass produces the hidden states for all
of those boundaries; Qwen is not separately re-prompted with a new user
message for every gold position.

The label adapter converts each selected hidden state into logits over all EAI
labels.

### 4. Calculate EOS-masked cross-entropy

The Stage 1 loss includes every target through the first EOS:

```text
CE(find)
+ CE(novel_1000 | find)
+ CE(grab | find novel_1000)
+ CE(novel_1000 | find novel_1000 grab)
+ CE(read | ...)
+ CE(novel_1000 | ... read)
+ CE(EOS | ... read novel_1000)
```

EOS padding after the first EOS contributes no loss. This prevents short plans
from receiving many duplicate EOS training terms.

### 5. Update the policy

Backpropagation updates the trainable LoRA and label-adapter parameters. The
reference sequence of length `T` supplies `T` direct learning signals, which
makes Stage 1 substantially more sample-efficient than trajectory-level
reinforcement learning.

### 6. Autoregressive semantic validation

After each Stage 1 epoch, validation does not use gold prefixes. The policy
decodes from its own predictions, and the graph-compiled DFA masks illegal next
labels. The generated plan is simulated and evaluated against the task's
SimpleTL goal.

The generation graph is therefore the hard-policy authority during decoding;
it does not manufacture the gold labels or replace Stage 1 cross-entropy. The
world graph and reward evaluator provide validation metrics in Stage 1, not the
Stage 1 gradient.

Reported metrics include:

- exact sequence and token accuracy;
- non-empty plan rate and average predicted length;
- DFA validity;
- goal success and grounded goal-state recall;
- temporal progress;
- world-constraint and combined reward scores.

### 7. Select and restore the best Stage 1 epoch

Stage 1 checkpoints are ordered by:

1. goal-state recall;
2. goal success;
3. positive-reward rate;
4. exact sequence accuracy;
5. token accuracy;
6. lower supervised loss as the final tie-breaker.

Only trainable parameters are copied into the in-memory best snapshot, avoiding
a second frozen Qwen copy. After all Stage 1 epochs, the best snapshot is
restored and saved as `<model-stem>.stage1.pth`.

### 8. Apply the exploration gate

Stage 2 starts only if the restored checkpoint meets configured minimums for
positive-reward rate, goal recall, and goal success. If the gate fails, the
Stage 1 checkpoint is retained and the command skips Stage 2.

## Stage 2: reinforcement learning fine-tuning

### Objective

Stage 2 combines a trajectory-level policy-gradient objective with the same
gold-token supervision used by Stage 1:

```text
L_stage2 = L_RL + supervised_weight * L_gold
```

The default `supervised_weight` is `0.5`. The two terms have different roles:

- `L_RL` reinforces or suppresses sampled behavior according to simulator
  outcomes.
- `L_gold` continues to provide the correct reference token at every gold
  position and limits destructive policy drift.

### 1. Reuse the restored Stage 1 objects

Stage 2 does not create a random classifier or replacement policy. It reuses
the restored Qwen, LoRA, label adapter, generation graph, world graph,
vocabulary, and compiled policy DFA. The Stage 1 optimizer is released, and a
new Stage 2 optimizer is constructed over the same trainable parameters.

### 2. Sample several on-policy trajectories

For each training example, the policy samples `N = --rl-num-samples`
trajectories. Each trajectory conditions on its own generated prefix:

```text
label_t ~ policy(label_t | task_prompt, sampled_labels_<t)
```

This differs from Stage 1 teacher forcing. Gold labels are not injected into
the rollout, because the simulator must evaluate the policy's genuine
behavior.

### 3. Apply the graph-compiled policy DFA

Every rollout has an independent DFA state. Before sampling a label, logits for
illegal transitions are set to negative infinity. The graph-defined policy
enforces such rules as:

- the first label is an action;
- object-taking actions receive an immediate compatible object;
- objects are followed by another action or EOS;
- zero-argument actions have the appropriate successor;
- EOS closes only a complete plan;
- task-context action and entity restrictions are respected.

The DFA guarantees structural legality, not task success.

### 4. Generate with batched KV-cached Qwen inference

Rollout generation runs under `no_grad`. All trajectories for one task are
evaluated as one Qwen batch and maintain separate sampled prefixes and DFA
states. When chosen labels have equal native-Qwen token widths, the KV cache is
advanced. Unequal widths cause one safe batched full-prefix/cache rebuild.

This avoids retaining sampling-time gradient graphs and avoids one Qwen forward
per trajectory at every label step.

### 5. Simulate each trajectory

Sampled labels are decoded into action events and executed by the deterministic
abstract simulator. It produces ordered action events and state snapshots from
the task's initial state.

For the book example:

```text
s0 = initial state
grab(novel_1000)
s1 includes holds_rh(character, novel_1000)
read(novel_1000)
s2 retains the held-object state and records the read event
```

### 6. Calculate task progress

In dense mode, the task score is:

```text
task_reward = grounded_goal_recall * ordered_temporal_progress
```

Grounded recall measures how many required facts/events were achieved.
Temporal progress measures the longest satisfied ordered SimpleTL prefix. For
`GRAB(book) then READ(book)`, grabbing only receives partial credit; reading
before grabbing cannot receive full temporal credit.

Binary mode instead uses `1.0` for complete SimpleTL success and `0.0`
otherwise.

### 7. Modulate progress with world constraints

Applicable source-state precondition constraints produce a score `C` in
`[0, 1]`. With constraint weight `w`, the final reward is:

```text
RL_reward = task_reward * ((1 - w) + w * C)
```

The default `w` is `0.25`. A compliant trajectory preserves its task reward;
violations discount it. Constraints cannot create positive reward when the
task score is zero.

### 8. Compute within-task advantages

For default mean-baseline REINFORCE, the sibling rollout rewards define:

```text
baseline = mean(R_0, ..., R_N-1)
advantage_i = R_i - baseline
```

A positive advantage makes the sampled trajectory more likely. A negative
advantage makes it less likely. If all sibling rollouts receive the same
reward, all advantages are zero and the RL term supplies no gradient for that
task; the supervised anchor still supplies a gradient.

### 9. Differentiably rescore sampled trajectories

Sampling itself used `no_grad`, so each sampled trajectory is replayed with
teacher forcing on its own sampled labels. This computes:

```text
log_policy(trajectory_i)
  = sum_t log policy(sampled_label_i,t | prompt, sampled_prefix_i,<t)
```

This is teacher-forced computationally, but its targets are the sampled labels,
not the gold labels. The same compiled DFA masks sampling and rescoring, so the
probability used by REINFORCE matches the sampling policy.

The policy loss is:

```text
L_RL = -mean_i[advantage_i * log_policy(trajectory_i)]
```

### 10. Rescore in memory-safe microbatches and add the gold anchor

Qwen rollout rescores are backpropagated in small microbatches, normally one
trajectory at a time. Gradients accumulate across every sibling rollout. The
gold reference sequence is then teacher-forced once more to calculate
`L_gold`. Only after both RL and supervised gradients have accumulated does the
optimizer perform one update for the training example.

### 11. Evaluate, select, and save the best Stage 2 epoch

After every RL epoch, the policy is decoded autoregressively with the graph DFA
and evaluated with the same sequence, simulator, SimpleTL, temporal, and
constraint metrics used for Stage 1 validation. Stage 2 checkpoints are ordered
by:

1. goal success;
2. goal-state recall;
3. temporal progress;
4. positive-reward rate;
5. shorter average predicted length;
6. exact sequence accuracy;
7. token accuracy;
8. combined RL reward score.

Only the trainable parameters of the best RL epoch are retained. That snapshot
is restored before final evaluation and saved to the configured two-stage model
path; checkpoint metadata records the selected epoch rather than the configured
last epoch.

## How the two stages differ

| Property | Stage 1 | Stage 2 |
|---|---|---|
| Primary signal | Correct label at every gold position | Reward for a complete sampled trajectory |
| Prefix used for primary signal | Gold prefix | Policy's sampled prefix |
| Simulator affects gradient | No | Yes, through detached reward/advantage |
| SimpleTL affects gradient | No | Yes, through task reward |
| World constraints affect gradient | No | Yes, by modulating task reward |
| Graph DFA | Autoregressive validation | Sampling, rescoring, and evaluation |
| Gold-token cross-entropy | Full objective | Auxiliary supervised anchor |
| Exploration | No | Yes, categorical sampling |
| Checkpoint policy | Best semantic epoch restored | Best semantic RL epoch restored |

Stage 1 is usually the more sample-efficient learner because every reference
trajectory supplies many direct token targets. Stage 2 is a conservative
semantic refinement: it can reward valid alternative plans and ordered task
progress, but its trajectory-level signal is noisier. The supervised anchor,
lower RL learning rate, limited RL epochs, and semantic checkpoint comparison
are therefore important safeguards.

## Principal implementation locations

- `dataset.py`: prompt fields, reference trajectory normalization, labels, and
  per-task context.
- `graph.py`: declarative generation concepts and constraints compiled to the
  policy DFA.
- `modules.py`: Qwen prompt encoding, pretrained label adapter, teacher forcing,
  and batched KV-cached rollout state.
- `reward.py`: abstract simulator, SimpleTL evaluation, recall, temporal
  progress, and combined reward.
- `world_graph.py`: world/trajectory concepts and action-precondition
  constraints.
- `rl_sequence_program.py`: rollout sampling, DFA masking, advantage calculation,
  differentiable rescoring, supervised anchor, and gradient accumulation.
- `main.py`: program construction, Stage 1 checkpoint selection and gate,
  Stage 2 lifecycle, evaluation, and checkpoint saving.
