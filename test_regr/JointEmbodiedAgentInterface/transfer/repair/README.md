# Fresh decoder repair campaign

Two independent source-only arms start from the same pretrained Qwen3-VL-8B-Instruct model. `native` uses its frozen native LM head for VLABench JSON; `joint` learns the Joint graph-label head. Both learn LoRA and the EAI head. Neither uses primary-role hints, a grounding residual, training DFA masks, or an allowed-mass penalty.

The frozen recipe is in `protocol.RECIPE`: four epochs, seed 42, accumulated batch 8, AdamW, LoRA LR 5e-6, graph-head LR 1e-4, weight decay .01, 10% linear warm-up and cosine decay, NF4/BF16. VLABench CE averages the present syntax, source-pointer and destination-pointer group means. Unknown pointer labels are skipped, including entire overlapping BPE tokens. Both arms add .1 preservation KL against adapter-disabled native Qwen on identical causal native-JSON source prefixes. EAI CE weight is 1. Physical controllers remain fixed.

Preservation KL also covers the native LM distributions at EAI causal label-prefix boundaries. `precision.py` identifies the standard bitsandbytes NF4/BF16 backend without replacing its arithmetic. Its policy is stored in checkpoints and checked by loaders. Full-vocabulary losses project only the required query positions through the frozen native LM head; no vocabulary entries are masked. Real-model alignment checks require exact cached causal/RoPE positions and forced prefixes, no earlier-logit change after future-label perturbations, native distribution KL ≤0.001 and the existing graph-logit tolerance. Raw maximum logit differences and greedy disagreements are recorded. Source-only probes established expected quantized roundoff (maximum native KL 0.00072, zero greedy disagreements over 25 decisions, zero future-label influence); the initial elementwise native-logit check was overly strict. Task-success selection thresholds remain unchanged. No optimizer update or confirmation scoring preceded this correction.

Historical VLABench 3,600/450/450 and EAI **350/88** identities are retained; this is an internal source experiment. The plan's EAI 352/88 count was incorrect: the canonical corpus and original generation-input archive contain 438 examples. Exact archived EAI observation contexts and order are verified before training. Original RGB bindings, numbered tags and gold pointers receive the same deterministic permutations. Corrected density references and their audit are frozen in separate artifacts; original files are preserved. No target scenes enter training. Prompt construction excludes gold roles and task-specific templates.

Commands (run model modules in the isolated model container):

```sh
python -m test_regr.JointEmbodiedAgentInterface.transfer.repair.prepare --config CONFIG --output CONFIRMATION
python -m test_regr.JointEmbodiedAgentInterface.transfer.repair.diagnose --config CONFIG --manifest HISTORICAL --arm replay --output DIAGNOSTICS
python -m test_regr.JointEmbodiedAgentInterface.transfer.repair.train --config CONFIG --manifest SOURCE --arm native --output NATIVE --seed 42
python -m test_regr.JointEmbodiedAgentInterface.transfer.repair.train --config CONFIG --manifest SOURCE --arm joint --output JOINT --seed 42
python -m test_regr.JointEmbodiedAgentInterface.transfer.repair.evaluate --config CONFIG --manifest CONFIRMATION --arm native-trained --checkpoint CHECKPOINT --policy shared-verified --output CONDITION
python campaign.py --root EXPERIMENT
```

`prepare.py` runs directly in the qualified LIBERO simulator environment. The host-only campaign runs directly by file path, claims completely unused physical GPU UUIDs, records container IDs, PIDs, commands, logs and exits, and never stops other users' jobs. It performs source forward/backward preflights with **zero optimizer updates**, freezes the native-Base source validation reference, then trains the two arms. Initialization and each epoch are retained. Checkpoints have an explicit representation tag and require this package's evaluator.

Selection uses greedy canonical source validation: EAI ≥47/88 and VLABench Progress within one point of native Base. Eligible checkpoints rank by Progress, unambiguous source-pointer accuracy, then earliest epoch. Failed gates stay failed; a best trained checkpoint can only be reported diagnostically.

`surface.py` is a lexical projection, not Python planning constraints. Exact public ID aliases and balanced JSON fences map to canonical pointers; semantic legality still comes exclusively from the existing DomiKnowS shared declarations compiled to DFA. Unknown IDs are rejected and legal wrong-object choices remain possible. Historical integer-only DFA results are preserved. Historical head transplants are named diagnostic interventions and do not enter either fresh arm.

Source validation and external evaluation accept only public anonymous aliases and canonical integer pointers. Private scene-object names never enter the normalization API. This prevents the source metric's entity grounding from resolving a predicted private name into the answer ID. Unknown aliases are wire-format errors; this post-generation codec check never masks logits, chooses another object or regenerates a plan. Source validation archives raw JSON/text, emitted tokens, conversions and errors before independent reference scoring.

Confirmation uses 20 LIBERO tasks × official states 35–39 only after an archived-use audit and official-state/scene overlap checks. Persistent reservations prohibit later target training/validation on these identities, including older manifests. Qualification requires identical calibration records and executor/bridge hashes. Four systems × two policies receive 800 fresh native executions with a 1,000-step horizon. Two primary trained-minus-Base no-DFA contrasts use 10,000 paired task-cluster bootstrap samples, seed 42, 97.5% intervals. Other comparisons are descriptive. Native success, completed success, abstract success, validity and representation conversions remain separate.

The campaign stops after these two arms and fixed evaluations. It does not tune on confirmation, repair executors, expand to RLBench, or start further training. Reports remain pending until their complete denominators and provenance checks pass.

Evaluation now defaults to `--input-protocol image-instruction-v1`. The model receives the user instruction, unchanged images with target-independent anonymous numeric tags, and an output API listing operation/argument names. It receives no object inventory, semantic names, action explanations, scene relations, fixture/movability/type/position metadata, primary-role hints, or grounding residual. Entity bindings remain internal to the pointer codec. The tags and generic API are explicit interface assistance, so this is not a claim of an entirely uninstrumented vision baseline.

`input_protocol.py` separates that model context from a DFA-only binding view. Optional shared constraints receive anonymous pointer bindings and declared static-fixture evidence; goals, references, task identities, answer templates and predicted roles never enter that view. Legality remains entirely in the existing DomiKnowS declarations compiled to DFA. No-DFA decoding receives no such constraint binding. `metadata-assisted-v1` preserves the historical prompt only as an explicitly named, separately fingerprinted protocol. Resume checks reject mixing the two.

`evaluation_campaign.py` can adopt the already-running source training after verifying the exact owned supervisor commands and Docker identities. It terminates only the old host orchestration/reporting PIDs before any confirmation scoring, preserves both training containers and their GPU PIDs, reuses the unchanged source-validation selections, and runs the same eight fixed confirmation conditions with strict inputs. It never launches training. `input_audit.py` checks real processor tensors and rendered prompts for all 100 frozen scenes under poisoned metadata/reference fields, without loading model weights or scoring goals. The protocol change creates a separate evaluation artifact root; archived results stay intact.

`preservation_audit.py` independently checks actual no-DFA versus repaired-DFA predictions. Every free greedy output whose normalized plan satisfies the DomiKnowS-compiled policy must retain its exact emitted tokens and canonical pointers; native alias spellings must also be accepted by the repaired projection. Legal wrong-object choices remain legal. Generation errors retain their denominators, paired input fingerprints must match, and successful constrained generations must satisfy the compiled policy. The audit opens no goal or execution-success files. Analysis requires its passing artifact. Already-running immutable campaigns use a separately fingerprinted reporting overlay for this final audit; their training and inference source snapshots remain unchanged.

### Executor-aware Shared DFA

The strict evaluator accepts `--policy shared-verified-capabilities` to compile the executor's declared operation set alongside the five Shared rules. `--policy shared-verified-executor` also enables the existing DomiKnowS holding, capacity, affordance, and compatibility constraints. The policy uses the existing bounded grammar and EOS rules. The executor profile declares action roles, effects, gripper capacities, and any initial holdings known from reset. Unknown facts remain unknown. Each profile must use the canonical roles supported by its decoder vocabulary.

Both Joint labels and native JSON pass through the same compiled policy and retain the strict model prompt. The fixed LIBERO executor supplies a single gripper known empty at reset and supports pick and place. The strict VLABench regression has no verified executor profile, so both new options use the same effective policy as `shared-verified`. No task patterns, reference destinations, or goal completion predicates are part of the extension.

`executor_experiment.py --root EXPERIMENT` replays the archived failures before launching four matched Joint epoch 2 conditions. It checks identical rendered inputs and exact preservation of compliant Shared greedy plans, runs the qualified simulator for each condition, and records paired native outcomes, rule traces, plan validity, and remaining grounding errors. The LIBERO episodes were previously scored, so the comparison is exploratory.

`evaluate.py --policy shared-verified-executor --preference visual-source` enables an inference-only soft preference for Joint source pointers in the strict LIBERO protocol. A DomiKnowS adjacency declaration compiles to a finite latent transition potential. The Joint scoring hook projects that potential to the legal pointer logits. The system uses frozen SigLIP cosine scores from clean RGB crops located by public numeric tags and the source phrase parsed from the instruction. It abstains when the source phrase or a confident legal visual match is missing. The default is `--preference none`. The mode does not change prompts, legal tokens, destination scores, or checkpoint weights.

`preference_experiment.py --root EXPERIMENT` compares a fresh visual-source inference and simulator run with a prior matched executor-DFA archive. It checks the policy and simulator contract, input hashes, and allowed token sets at biased decisions. Results include applied biases, paired prediction changes, grounding and native success on the same 100 previously scored scenes.
