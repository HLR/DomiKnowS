REPRODUCED IN CURRENT DEVELOP
D01: Direct miota decoding receives local/softmax and the previous ILP world,
     before the winning assignment is populated. Both populate modes fail.
D02: The loss-form ILP leaf reader returns None for binary [0] or [1] because
     it indexes the absent second element of the one-element ILP tensor.
D03: Compiled ILP-mode binding pairs left(x,y) with right(x,y), despite the
     formula specifying right(y,x). Same-order control passes.
D04: Two/three-hop existential conjunctions lose a known witness at unequal
     operand scopes (4 versus 2 rows). One-hop control passes.
D05: Grounding mismatch logs an error and returns an empty constraint instead
     of failing explicitly. This is the dangerous silent-failure behavior.
D06: Default top-four pruning drops a known Boolean witness in an 11^6 joint
     grounding. A small exact control passes. Hard decoding uses this path.
D07: Same script plus different working directories resolves to the same
     GurobiSolution.sol path. This establishes collision risk, not a race run.
D09: collectInferredResults(flag, 'ILP') returns empty for a populated child.
D10: Nonoptimal-status handling calls computeIIS even after TIME_LIMIT;
     timeout is not proof of infeasibility. Model-status double used.
T01: Product implication has finite loss but NaN antecedent gradient at
     a=1e-30,b=0.2 in FP32. This is a training bug, not an ILP optimizer bug.
